# Мини-система денежных переводов на Go

Проект, реализующий систему денежных переводов между пользователями.  
Разрабатывался поэтапно, с последовательным усложнением архитектуры — от простых структур до конкурентной обработки транзакций с помощью worker pool и защиты от гонок данных.

---

## Версии проекта

Каждая версия соответствует отдельной ветке на GitHub:

| Ветка | Часть | Что реализовано |
|-------|-------|-----------------|
| [`v1`](../../tree/v1) | Часть 1 | Базовая структура `User`, методы `Deposit`/`Withdraw`, обработка ошибок |
| [`v2`](../../tree/v2) | Часть 2 | Структура `PaymentSystem`, очередь транзакций, массовая обработка |
| [`v3`](../../tree/v3) | Часть 3 | Конкурентность: worker pool, каналы, `sync.WaitGroup` |
| [`v4`](../../tree/v4) | Часть 4 | Защита от гонок: `sync.Mutex` в `User` |

## v4 — Защита от гонок данных

**Ветка:** [`v4`](../../tree/v4)

**Что сделано:**
- В структуру `User` добавлено поле `mu sync.Mutex`
- Методы `Deposit` и `Withdraw` защищены:
  - `mu.Lock()` в начале
  - `defer mu.Unlock()` для гарантированного освобождения
- Проведено тестирование с флагом `-race` — гонок нет

**Почему:**
При параллельной обработке несколько горутин могут одновременно изменять баланс одного пользователя.  
Без синхронизации это приводит к **data race** и некорректным результатам.  
`sync.Mutex` гарантирует, что только одна горутина имеет доступ к балансу в конкретный момент времени.

## Итог

Проект полностью реализует **конкурентную систему денежных переводов**:

- Пользователи и их балансы
- Очередь транзакций
- Многопоточная обработка через Worker Pool
- Безопасная работа с данными через мьютексы
